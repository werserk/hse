# hse.werserk.dev: как разложить beta-кейсы по темам

Дата: 2026-11-19. Только предложение: контент, `entry.json` и URL не менялись.
Источники: `~/Projects/hse/content/*` (заголовки и тексты четырёх beta-кейсов, эталоны LOTER и Runtime), `~/Projects/hse/AGENTS.md`, отчёт `thr_4vzmpawai8/hse-registry-candidates.md`.

## Итог

- **Что не так сейчас.** Каждый beta-кейс повторяет файл-источник: «читлист к КР», «формулы из ДЗ», «13 типов задач». Внутри одного кейса лежат несвязанные темы, а в названиях стоят событие и формат («КР-2», «Читлист», «ДЗ1–4») вместо предмета.
- **Что предлагаю.** Резать по темам курса, то есть по лекциям: один кейс отвечает на один вопрос, к которому хочется вернуться. Контрольные, пробники и печатные листы собрать в один «опорный» кейс на курс, который ссылается на тематические кейсы.
- **Масштаб.** 4 beta-кейса превращаются в 14 опубликованных кейсов и 3 карточки `planned`. Почти весь текст переносится, а не пишется заново. Дописывать с нуля нужно в основном Монте-Карло (байес, вероятность) и стыки между главами.
- **От владельца нужно:** утвердить принципы (§1) и раскладку (§2–5). После этого правки идут отдельными задачами по одному кейсу.

```
Сейчас (4 кейса = 4 файла)            Предлагается (кейс = тема)
──────────────────────────            ─────────────────────────────────────────────
МК «КР-2: как узнать задачу…»   ──►   Вероятность и распределения · Цепи Маркова ·
                                      Байес для параметра · Пробник КР-2 и карта задач
                                      (+ planned: Монте-Карло · SIR)
ДУ «Читлист: 13 типов задач»    ──►   Разностные уравнения · Системы на плоскости ·
                                      Первые интегралы и УЧП · Линейные 2-го порядка ·
                                      Карта задач по ДУ
ВГ «Формулы … ДЗ1–4»            ──►   Харди–Вайнберг и LD · Дрейф и Ne · Коалесцент ·
                                      Сводка формул (+ planned: ARG)
НИС «Skygrid: Gill et al.»      ──►   тот же кейс, новое имя, глава 2 → ссылка на «Коалесцент»
```

## 0. Модель страницы кейса (владелец, 2026-11-19)

```
┌──────────────────────────────────────────────┐
│ обложка · название · summary                 │  шапка
├──────────────────────────────────────────────┤
│ [Слайды] [PDF] [Лист на печать] [Код] [Ссылка]│  ряд материалов (вспомогательные)
├──────────────────────────────────────────────┤
│ ТЕЛО: конспект прямо на странице             │  одно читаемое тело:
│   или короткая инфо-страница                 │  конспект (тема) или инфо-страница (опорный кейс)
└──────────────────────────────────────────────┘
```

Отсюда следует: у кейса **ровно одно тело**. У тематического кейса это конспект, у опорного — инфо-страница: карта задач, что внутри листов и пробника, ссылки на темы. Всё остальное (колода, PDF, виджеты, ссылки) — материалы в ряду. Doc-only кейсов (только PDF без тела) в раскладке нет: у каждого PDF есть страница, которая объясняет, что он даёт. У каждого кейса нужна обложка, сейчас она есть только у LOTER и Runtime. В таблицах ниже столбец «Тело» указывает, что именно читается на странице.

## 1. Принципы (кандидат в правило `~/Projects/hse/AGENTS.md`)

Эталоны: **LAI: LOTER** (тема одна, пять глав от задачи к ограничениям, ~49 КБ) и **LAI: Runtime** (то же, ~39 КБ).

### Декомпозиция

| # | Правило | Проверка |
|---|---|---|
| D1 | **Кейс = тема, а не файл.** Один кейс отвечает на один вопрос предмета: метод, модель, класс задач. Обычно это объём одной лекции или одной статьи. | Вопрос кейса умещается в одно предложение «Как…/Почему…». |
| D2 | **Резать по структуре курса (лекции, разделы программы), а не по контрольным и ДЗ.** Контрольная — это срез по нескольким темам, а не тема. | В названии тематического кейса нет «КР», «ДЗ», «коллоквиум». |
| D3 | **Размер:** 3–6 глав, конспект примерно 15–50 КБ. Если глав больше 7 или они не опираются друг на друга, это несколько кейсов. Если кейс получается меньше 10 КБ, его стоит влить в соседний. | Главы идут цепочкой: каждая использует предыдущую. |
| D0 | **Одно тело на кейс:** конспект (тематический кейс) или короткая инфо-страница (опорный). Колода, PDF, видео, код — материалы в ряду, не второе тело. | Страница кейса читается без открытия материалов. |
| D4 | **Кейс читается сам по себе:** вопрос и пререквизиты (ссылками на другие кейсы) → главы → ловушки и ограничения → источники. | Читатель, пришедший по ссылке, не обязан открывать соседний кейс, чтобы понять первый абзац. |
| D5 | **Одна мысль живёт в одном кейсе.** Вывод формулы есть только в одном месте, остальные кейсы дают абзац-напоминание и ссылку. Это касается и связей между предметами: например, коалесцент в «Вычислительной геномике» и в Skygrid. | Поиск по формуле находит один вывод. |
| D6 | **Один опорный кейс на курс** (по желанию): карта «признак в условии → кейс и глава», пробники с решениями, печатные листы на весь курс. Своих выводов в нём нет, только ссылки. | Печатный лист по одной теме скачивается из этой темы, лист на весь курс — из опорного кейса. |
| D7 | **Темы курса, которых ещё нет, видны карточками `planned`**: карта предмета полна, даже если текст ещё не написан. | Раздел курса на сайте показывает всю программу. |

### Названия

| # | Правило | Плохо → хорошо |
|---|---|---|
| N1 | **Название говорит о предмете.** Формат, событие, версия и номер ДЗ в название не попадают, им место в `event`, `downloads` или в тексте. | «Читлист: 13 типов задач» → «Разностные уравнения» |
| N2 | **Шаблон «Тема: уточнение»**, 2–6 слов. Термин такой, каким его называет курс и каким его станут искать. Префикс серии ставится, когда серия есть (LAI:). | «Skygrid: Gill et al. (2013)» → «Skygrid: численность популяции по нескольким локусам» |
| N3 | **`summary` — вопрос, на который отвечает кейс**: одно предложение до ~160 знаков, начинается с «Как/Почему/Когда», содержит ключевые термины. Без формул (карточка их не рендерит) и без перечня глав. | «Четыре главы по основным формулам курса…» → «Как случайная выборка потомков меняет частоты аллелей и почему популяцию описывает эффективный размер.» |
| N4 | **Подписи скачиваний описывают содержимое и назначение**, а не версию файла. | «Читлист v3.2 (PDF, 7 стр.)» → «Лист на печать: цепи Маркова и байес (PDF, 7 стр.)» |
| N5 | **Заголовки глав описывают действие или понятие**, а не код источника и не жаргон. | «M7. Система разностных уравнений…» → «Системы: степень матрицы»; «Цепь из слов» → «Построить цепь по условию» |
| N6 | **`event` — повод, а не повтор названия курса**: «КР-2, 12.11.2026», «НИС АДНЖ, доклад №3». У тематического кейса без повода поле пустое. | `event: "Дифференциальные уравнения"` в курсе «Дифференциальные уравнения» → пусто |
| N7 | **Slug английский и тематический**: `markov-chains`, а не `kr2`, `cheatsheet`, `formulas-hw1-4`. | |

Опорный кейс курса — единственное место, где название может содержать событие («Пробник КР-2…»): контрольная и есть его тема.

Набросок правила для `AGENTS.md` (на английском, как остальной файл; вставлять только после согласования с платформенным тредом, этот файл принадлежит ему):

```md
## Decomposition and naming

- A case is a topic, not a file: it answers one question of the subject (a method, a model, a class of problems),
  usually one lecture or one paper. Cut along the course's own structure, never along assessments or homework.
- 3–6 chapters, each building on the previous; about 15–50 KB of konspekt. More than 7 loosely related chapters is
  several cases; under ~10 KB, merge into a neighbour.
- A case reads alone: question and prerequisites (links), chapters, traps and limits, sources. A derivation lives in
  one case; others recap in a paragraph and link.
- One readable body per case: the konspekt inline on the case page, or a short info page for a hub. Decks, PDFs,
  widgets and links are supporting materials in the row, never a second body. No PDF-only cases.
- At most one hub case per course: problem map (cue → case/chapter), mock tests, whole-course print sheets. It links,
  it does not derive. Only the hub may name an assessment in its title.
- Topics of the programme not written yet appear as `"status": "planned"` cards.
- Title: «Topic: qualifier», 2–6 words, the course's own term. No format, event, version or homework number in it.
- `summary`: the question the case answers, one sentence ≤ 160 chars, «Как…/Почему…», no formulas.
- Download labels say content and use, not file version. `event` is the occasion, never the course name again.
- Slugs are English topic names (`markov-chains`, not `kr2`). Reference examples: `genomics/loter`, `genomics/runtime`.
```

## 6. Риски и открытые вопросы

- **URL.** Beta-адреса (`/beta/monte-carlo/kr2/` и т. п.) исчезнут. Они не в индексе, но владелец мог ими делиться. Предлагаю не делать редиректы: это beta.
